本页说明如何安全接入 FGAuth 验证服务器、管理多个机器人账号与房间、处理好友申请和私信，并明确 `v1.6.0` 中玩家身份与 OP 权限的实际行为。

## 适用版本与前置条件

- **适用版本**：NEMCBridge `v1.6.0`。
- **前置条件**：
  - 已有一个可用的 FGAuth 验证服务器（默认 `https://fgauth.ucket.top`；自建站需支持下述安全开房和房间票据）。
  - 每个计划同时开房的房间，各准备**一个独立的网易账号**与对应的机器人令牌。

## FGAuth 鉴权与信任机制

| 用途 | 自建 FGAuth 需要提供的能力 |
| --- | --- |
| 房主开房（v1.6.0） | 安全协议 2、机器人令牌验证、房间号安全回传并签发访客核验票据；缺失票据时不能开房。 |
| 访客昵称核验 | 默认由桥接直查网易，仍需要 FGAuth 确认并授权当前房间；网络回退需验证站提供访客资料查询接口。 |
| 私信及账号资料 | 私信需 `friend_chat` 凭据，头像和昵称需账号资料接口；不能用一个版本号保证这些可选功能全部可用。 |

历史资料中的 NEMCBridge `v0.1.9` 是客户端最低版本检查，不是 FGAuth 的最低版本。

1. 在控制台「设置」填入 FGAuth 地址。NEMCBridge 与验证站之间使用一次性挑战、X25519 临时密钥协商、Ed25519 服务端签名与 AES-256-GCM 加密。
2. 首次通过 HTTPS 连接验证站时，程序会将服务端公钥写入数据目录的 `auth-trust/`。后续若公钥发生变化，程序会直接拒绝连接以防中间人篡改。
3. 开房成功后，程序会加密回传房间号用于审计；若回传失败，程序会关闭新建房间并按退避策略重试。

> **不要盲删 `auth-trust/`**。如果遇到公钥不匹配，请先通过可信渠道确认验证站是否进行了合法迁移，再由管理员更新对应 `.pub` 文件。

## 多账号与多房间配置步骤

从 `v1.2.0` 起，NEMCBridge 不再限制国际服和房间数量，可以同时为同一台国际服开多个房间，也可以分别连接不同版本的国际服。

1. **在 FGAuth 准备独立令牌**：多房间场景下，务必在 FGAuth 中为每个令牌**明确指定各自的网易账号**，不要全部设为「跟随当前使用的账号」。
2. **添加账号**：进入控制台「网易账号」，添加各机器人令牌。配套新版 FGAuth 会返回公开昵称与头像（缓存于 `account-profiles.json`，不含令牌）。
3. **绑定国际服**：进入「桥接」，点击目标国际服的「绑定」选择账号：
   - **每个账号最多绑定一个国际服或一个[选服大厅](../backends-and-gateway/#选服大厅)**；同一个目标可绑定多个账号。
   - 绑定、切换和解绑会立即保存，运行中也支持调整（绑定到已启动的国际服会自动启动该账号的房间；解绑只停止该账号的房间）。
   - 正在开房的账号不能直接移除，需先解绑或停止。
4. **调整房间参数与启停**：
   - 房名、密码、人数上限按房间独立保存；修改正在运行的房间配置前需先停止该房间。
   - 在「概览」用房间卡片启动或停止；大厅绑定在「桥接」管理。

### 房间人数上限规则

| 项目 | 规则说明 |
| --- | --- |
| 可配置范围 | `2–30` 人，默认 `10` 人（**包含房主机器人**）。 |
| 账号权益限制 | 普通账号、不灭钻石、下界领主对应的上限分别为 `10`、`20`、`30`，以网易实际接受的账号权益为准。 |
| BDS `max-players` | 须能容纳所有房间接入者与国际版直连玩家；调大 `max-players` **不会**提高单个网易房间名额。 |
| 超出单房人数 | 可通过多账号开多个房间，或启用 [自动转服网关（Beta）](../backends-and-gateway/#自动转服网关突破10人限制-beta) 释放大厅名额。 |

## 好友申请与私信

进入「网易账号 → 对应账号的『好友』」，无需开房即可管理好友：

- **好友申请**：默认每 30 秒自动检查并同意待处理申请（每轮最多 20 条、间隔 1 秒），可在该账号的「好友申请」页面关闭自动同意并改为手动处理。自动同意失败会独立重试，不会导致房间断开。
- **发送私信**：点击好友即可发送 1–500 字文本到网易启动器聊天（支持 `Ctrl / ⌘ + Enter`）。
  - **仅支持发送**，不接收或同步对方回复。
  - 发送记录和草稿仅保存在当前浏览器页面（每好友最多 50 条、最多 20 个会话），刷新后清空。
  - 需配套支持 `friend_chat` 凭据的 FGAuth。

## 访客身份、昵称核验与 OP 权限（v1.6.0 行为）

按当前版本配置，不要套用旧版 OP 管理办法：

- **访客昵称核验**：默认按房间绑定的网易 UID 直查。直查因网络故障无法完成时，使用同一房间票据请 FGAuth 核验**同一个 UID**；明确拒绝或资料无效时不走网络回退。核验失败不采用客户端自报昵称。自动转服沿用该次已核验的身份。
- **房主会话和保活**：房主旧会话失效不等于访客查询超时，恢复会话取决于验证站支持的接口。不要用两套 FGAuth 同时管理同一账号。FGAuth `v1.5.2` 在收到并确认有效的开房报告后，会关闭本实例中房主账号的保活，不影响其他账号或已建立房间的心跳。
- **稳定存档身份**：普通房间与自动转服均基于网易大厅确认的 `netease_uid`（缺失时用 `netease_uuid`）生成稳定的后端 UUID（沿用 `v1.5.1` 算法）和数字兼容 XUID，用于隔离每个账号的背包与位置。**该兼容 XUID 不是微软官方 Xbox XUID**，不能用于正版查询或权限凭证。
- **OP 权限归属（v1.5.4 起）**：**OP 权限交回各国际服后端自行管理**，桥接不再从桥接侧名单补发 OP，也不要按昵称迁移旧 OP 权限。
  - `v1.5.3` 有过托管 BDS 授权弹窗；正式 `v1.6.0` 没有该入口。Windows BDS `26.60` 的旧版原生 OP 持久化限制和证据见[版本与下载](../releases-and-downloads/#版本冲突与待核清单)。

## 成功标志

- 控制台「网易账号」显示已绑定账号的昵称与状态，无重复占用提示。
- 各房间稳定在线，掉线后能自动重试并更新房间号。
- 网易端玩家进服后显示正确的网易昵称，且不同账号的背包与出生点互不串号。

## 常见失败与排查

| 现象 | 原因与处理 |
| --- | --- |
| 机器人反复掉线并重开，房间号不断变化 | 排查同一网易账号是否在手机、其他进程或多个房间同时登录；检查 FGAuth 鉴权与网络稳定性。 |
| 多房间添加后报错「账号已被占用」 | 在 FGAuth 中为每个令牌绑定了相同账号或都设为「跟随当前账号」，请分别为各令牌指定独立网易账号。 |
| 好友页提示「私信不可用」或资料页提示升级 | 所连 FGAuth 版本偏旧，未提供 `friend_chat` 或 `account_profile` 接口；升级 FGAuth 即可，不影响普通开房。 |
| 升级后玩家背包重置或原 OP 失效 | 跨大版本切换了后端身份算法或不再从桥接补发 OP 时不会自动迁移旧档/旧 OP，请先备份世界并按核验身份在后端重新核对。 |
